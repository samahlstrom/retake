# Linked folders — implementation contract

Retake must let an owner select only the folders they want, across drives, without copying footage. Preserve folder trees and review history. Existing installations retain their present folder until the owner changes it; never silently disconnect current work.

## Data and access
- Add owner-only GET/POST /api/library on the local folder hub. GET returns computer name, platform, native_picker capability, linked folders [{id,path,subfolders,available}], and a revision. POST atomically replaces folders from that list (id retained for Locate), with revision conflict detection. Paths may be absolute or home-relative; validate actual readable directories, canonicalize and deduplicate; reject overlapping roots rather than scanning twice. Empty selection is valid and persists across restarts. Missing existing roots remain visible/offline, never removed automatically. Newly selected missing/file/invalid paths fail without partial writes.
- Persist a small library manifest beside the application config, keyed by the original home identity; use the home's .retake directory only for embedded hubs with no config path. This keeps other links usable when the original source drive is offline. Keep original home/store identity (and share tokens). No footage copies, symlinks, moves, deletes, or generated review modifications. Existing root is the implicit initial link. Scan only the configured roots. Include-subfolders is explicit. Restrict symlinks to the selected roots; do not discover unrelated trees through a symlink. Project URL names must remain stable when narrowing the old root to a selected child; collision-resistant names for additional roots must remain stable across reorder/remove/re-add/restart. Preserve original names for existing demo links. Removing stops discovery and access through stale /p paths; do not stop an active edit silently (refuse removal/relocation with a useful error while busy).
- Linking does not broaden existing share access. Old unscoped home tokens retain access to original-root projects only; new roots need an explicit video share. Scoped video links continue to work for still-linked projects. Never expose library paths/host details or picker to viewers.
- Locate changes a retained link's path and keeps stable project URLs by relative path; review data stays with the actual directory. Offline link is shown even with zero cards.
- New installs must start with an empty library and an explicit folder choice, not a silently selected whole Movies/Videos tree. Existing config.folder behavior and CLI retake open folder stay compatible. If a configured library manifest exists, retake start must open that library even when the original folder is offline; do not send the owner back to first-time setup. Prefer reusing startup/setup and setting the application's storage home for new installs if needed.

## UI
- Existing calm Svelte design/tokens/icons remain the reference. Owner local home gets an obvious Add folders button and Linked folders entry; Settings' old single Videos folder control becomes this same manager, not two conflicting controls. Hosted/viewer pages must not offer local folder controls.
- Show 'Folders on <computer name>' and clear text 'These folders are on the computer running Retake.' Browser hostname alone cannot prove it is this Mac; do not confuse SSH-forwarded tower with Mac.
- Add opens server-folder browsing with checkboxes for multiple selections, keyboard focus, Up, editable path (external drives), selected path list, Include subfolders per selection, Cancel and Add N folders. Default include subfolders true. No mutation until confirmed. Visible copy: 'Retake will link these folders. Your files stay where they are.' Also state linking does not share them.
- Each linked folder has path, computer, availability, subfolder setting, Locate folder when offline, and Remove from Retake. Removal confirmation says 'Files stay on your computer.' Empty library has Add folders and clear instructions. Inline errors preserve selections. Mobile 390px works without horizontal overflow.
- Native picker: local macOS owner can invoke a server-native multiple-folder dialog. Finder folders can be dragged into that native dialog. Do NOT run native dialogs during automated tests. Only enable the native picker in desktop app mode for local owner requests; reject shared and forwarded HTTP requests. SSH forwarding is indistinguishable from a local request, so always name the server computer, never infer This Mac from a loopback URL. A native-picker result is a candidate list, not automatic linking; still show confirmation.
- Browser drop must never guess absolute paths from names or upload files. Support a same-app drag from the server folder browser into selection, and explain external Finder drop limitations truthfully. If native picker is available, dropping external folders can lead to the native picker for confirmation, otherwise show clear guidance to Choose folders on the named computer. Do not imply direct browser Finder drop works without a bridge.

## Proof
- Targeted tests first, different RED and GREEN authors. Synthetic fixtures only. Verify persistence/empty/offline/invalid paths, traversal/symlink boundaries, scopes, unchanged URL/history, and no source mutation. Native dialog behavior tested using injection, never open desktop windows.
- Capture before/after for owner desktop/mobile, selector/confirmation, linked/offline/empty/error/remove states and viewer absence. Store public-safe evidence on GitHub issue. Independent visual review and full Go/web checks before shipping.

## Wire format

`GET /api/library` returns `{computer:{name,platform}, native_picker, revision, folders:[{id,path,subfolders,available}]}`. Revision is numeric; mutations send `{revision,folders}`. A new folder omits id; a retained id with a new path is Locate. `POST /api/library/pick` returns `{paths:[absolute paths]}` and never saves them.
