# Roadmap

## Decisions so far
- **Solo first, team later.** No real-time co-editing.
  - Each person's comments are their own append-only takes, merged by timestamp.
  - The agent is the only writer of the timeline.
  - People who want to review together use a video call. No follow-me mode.
- **The review side never renders.** A version is any video file, or later a timeline revision previewed from the
  editor's cache.
- **Comments go in a sidebar,** not on the timeline.
  - The newest version shows only the agent's questions.
  - Flipping back to an older version shows its notes as they were resolved (✓ plus a one-line change, or ? plus the
    question).
  - A push is rejected unless every open note is answered or has a question.
- **Images.** While recording, the reviewer can drag or paste images onto the video. They're pinned to that moment and
  that spot, and stored as review-only assets.
- **Stack.** Go for the server (one binary with the page embedded). Svelte 5 + TypeScript + Bits UI for the page.
  Rust for the future editor engine.
- **The player plays chunked playlists (`.m3u8`) as well as single files,** so the editor's cached draft segments can
  stream later.

## Milestones
1. **Local player at parity.** Done.
   - The Go server and the Svelte page match the legacy player.
   - Same take format, so `review notes` still reads it.
   - Audio chunks are buffered in IndexedDB until the server confirms them.
   - The player can play `.m3u8` versions.
   - Playwright end-to-end test on generated media. CI workflow.
2. **Notes, agent API, questions.** Done.
   - Port `notes.py` to Go, with golden tests against the Python output.
   - whisper.cpp transcription.
   - CLI with `--json`, plus an MCP server.
   - Note states, the sidebar, image drops, and `retake watch`.
3. **Sharing and team mode.** `retake share` over an HTTPS tunnel, accounts and roles, Postgres + S3, remote MCP,
   Docker Compose.
   - 3a, done: share links, roles, hashed tokens, `retake share`, remote `/mcp` ([spec/team.md](../spec/team.md)).
   - 3b, done: `retake serve`, a self-hosted server for many projects: sign-in links and sessions, members, uploads
     (tus) and `retake push --remote`, Postgres + S3 drivers, Docker Compose ([spec/server.md](../spec/server.md),
     [deploy/README.md](../deploy/README.md)).
   - Left: a web admin page, per-person sidebars, redacting server paths, presigned media or a CDN.
4. **Release.** Installers, docs, a CC0 sample project, then the hosted service.
   - Done, short of publishing: versions from tags, release archives, `scripts/install.sh`, the docs, the sample
     project and third-party notices ([releasing.md](releasing.md)).
   - Left: publishing (below) and the hosted service.

## Editor track (after milestone 2)
1. Timeline schema and anchor resolver. Done (slice 1).
2. Shot renderer with a content-addressed cache and render manifest. Done (slice 1).
3. Review bridge. Done (slice 2).
4. Asset catalog. Done.
5. Graphics renderer. Done (slices 1 and 2: Skia layers, keyframes, QuickJS expressions).
6. A shared library of graphics, styles and edit recipes. Done (slice 3, [spec/components.md](../spec/components.md)):
   - components as JSON (a props schema, templates, kit tokens, expressions), pinned by a lockfile and expanded into
     the cache keys, so a component change re-renders only its elements, and upgrades are per element;
   - brand kits with tokens and house rules that `retake-edit lint` checks; storybook previews;
   - static registries (`retake lib add|search|pack`), edit recipes without media, and the agent tools;
   - a starter library of ten CC0 components and a kit (`library/`).
   - Left: publishing a registry somewhere (owner's call), Lottie leaves, the web preview of a component (CanvasKit).
7. Closing the pilot's gaps. Done (slice 4): perspective and corner pins, blend modes, opacity groups, masks and track
   mattes, Lanczos and unfiltered resampling, delogo, Pillow-like text metrics, `expr_lib`, audio streams, loudness
   targets and a master bus, and external raster backends (`retake-raster/1`) so existing drawing code (Pillow
   scripts) can be a component.
   - Left: continuous clocks for inserts and overlays (owner's call: frame grid or exact times), repeaters and asset
     facts in components (`$each`, image sizes and text widths at expansion), span proxies, the catalog resolving
     `proj:` ids and registering derived assets, smaller manifests, glyph advances that match Pillow exactly.

## Before publishing
Done:
- The e2e legacy mode, `scripts/legacy-parity.sh` and the golden regeneration require an env var; no default path.
- notes.md names the takes' author, or "the reviewer", instead of the legacy owner. The golden tests map that one
  difference explicitly.
- docs/editor-design.md uses neutral examples. The owner's original is kept out of the repository, in `docs/private/`.
- THIRD_PARTY_NOTICES.md, generated by `scripts/notices.mjs` and checked in CI.

Left (the checklist is in [releasing.md](releasing.md#before-the-first-public-release)):
- Pick the name and license, then add LICENSE and update go.mod's module path if the name changes.
- Run CI on GitHub once, since the workflow has only been linted locally.
- Decide what the history publishes: earlier commits hold the owner's private notes.

## Open decisions (owner)
- The name. "retake" is a working name.
- License. AGPL-3.0 for the server and Apache-2.0 for the client is the recommendation, not decided.
- Graphics: native Skia from data plus JS expressions, or TS web pages in headless Chrome.
- Pilot bar: is a close per-frame match to a reference render enough?
- C flip: the matching moment, or the same clock time?
- License gate: block publishing on review-only assets, or warn?
